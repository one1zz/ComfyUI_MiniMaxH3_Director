# 动作修复 (Motion Fix)

MiniMax H3 Director 的分段动作修复：把高动作密度段用**整数帧保持**放慢，采样后再**精确恢复**到源帧数。仅 `v2v` / `rv2v`，且需要在时间轴上逐段勾选。原声不会被重定时。

> 这份文档与代码里的能力矩阵 `director/motion_pack.py::motion_capabilities()` 同源。遇到组合冲突时，运行报告会输出同样的提示。

## 接线与开关

1. 把 **MiniMax H3 Director Motion Fix** 节点接到导演台的 `motion_fix` 口（不接 = 行为与主分支一致）。
2. 在时间轴上给需要放慢的段点「动作修复」徽标，或在段面板/全局面板勾选。
3. 节点提供默认值：`mode`（uniform/adaptive）、`dilate`（倍率）、`source_init_denoise`（源 latent 部分去噪）、`audio_recover`、`gate_*`、`min_frames`、`max_slowed_frames`、`fail_fallback`。逐段「倍率」可覆盖节点默认。

## 输出开关（默认关，显式开启才生效）

| 开关 | 默认 | 说明 |
|---|---|---|
| 精确导出 `exactExport` | 关 | 每段导出严格等于源/界面窗口；有相位差的接缝改用像素重编码钉入，不裁剪上一段。**原声 + 段间引导时自动启用**（避免源声漂移），可在输出栏显式关闭。 |
| 参考补齐 `refPadToGrid` | 关 | 把参考视频末尾用静止帧补齐到 17n+5 再送入官方节点，避免官方向下吸附（如 69→56）丢尾帧；代价是参考尾部一小段静止。 |

## 能力矩阵（组合冲突 + 规避）

| 组合 | 状态 | 提示 / 规避 |
|---|---|---|
| v2v / rv2v | ✅ | — |
| 段间引导 off / guide | ✅ | — |
| 段间引导 continue | ✅ | 同尺寸二采保留前缀硬锁；放大二采不保留（前缀仍随后裁掉） |
| 二采 refine | ✅ | 与动作修复叠加可用 |
| 放大二采 upscale | ⚠️ 提示 | 前缀硬锁不保留；如需硬锁请用同尺寸二采 |
| SelfLift | ⚠️ 降级 | 本段自动跳过动作修复（二选一） |
| 连续放慢段，前后倍率不同 | ✅ 自动规避 | 音频不再切上一段放慢 latent，改用实时展开并提示 |
| 不整除 22 的倍率 | ⚠️ 提示 | 钉入窗口按链路取 39/56；不整除任何窗口的倍率该段边界硬切 |
| 放慢总长 > 362 | ⚠️ 提示 | 超出 H3 训练区间，画质/显存/耗时未验证 |
| 放慢总长 > `max_slowed_frames` | ⚠️ 软限 | 仅提示，可继续（风险自负）；> 3600 硬报错 |
| 原声 + 段间引导 | ✅ 自动 | 自动启用精确导出并提示 |
| 静音 / 生成声 | ✅ | 生成声按 hold 组拼回实时 |
| 语义桥 Semantic Bridge | ⚠️ 提示 | 兼容性组合（非蒸馏任务），未充分验证，可关闭作 A/B |
| FaceRefine | ✅ | 在恢复实时帧后修脸 |
| 非 24fps | ⚠️ 提示 | 音频时基按 24fps 设计 |
| 选择性运行 / 分段导出 / 拼接 | ✅ | 缓存内的放慢 `.pre` 会自动恢复为实时帧 |

## 已知限制

- **放大二采 + 引导+重绘**：前缀硬锁不保留（前缀帧本来就会被裁掉，接缝由钉入帧维持）。
- 放慢后总长超过 H3 训练区间（约 124–362）画质未验证；默认软上限 512。
- 音频时基按 24fps 设计。
